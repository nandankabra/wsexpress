# ShipTrack — Requirement Traceability Matrix

28 requirements derived from the project brief (no PDF was attached to the build request; this
matrix maps every named requirement in the brief text to its concrete implementation). Each row
was verified against the running `docker compose` stack — see
[PROFESSOR_DEMONSTRATION_GUIDE.md](PROFESSOR_DEMONSTRATION_GUIDE.md) for full curl transcripts.

| # | Requirement | Service | Class(es) | Endpoint | Demonstration Method | Verification Steps |
|---|---|---|---|---|---|---|
| 1 | Microservices architecture (independently deployable services) | All 10 | 10 `*Application.java` main classes, each its own Maven module + Dockerfile | N/A | `docker compose ps` shows 10 separate containers | `docker compose up -d`; confirm 10 app containers + 4 infra containers healthy |
| 2 | API Gateway — single entry point | api-gateway | `ApiGatewayApplication`, `application.yml` routes | `http://localhost:18080/**` | All client traffic goes through the gateway; direct service ports are only for debugging | `curl gateway/api/shipments` succeeds; gateway routes to `SHIPMENT-SERVICE` via Eureka |
| 3 | Service discovery | discovery-server + all clients | `DiscoveryServerApplication`, `spring-cloud-starter-netflix-eureka-client` in every other service | `http://localhost:8761` (dashboard/API) | Eureka dashboard lists all registered instances | `curl http://localhost:8761/eureka/apps` lists AUTH-SERVICE, SHIPMENT-SERVICE, etc. |
| 4 | Centralized configuration | config-server + all clients | `ConfigServerApplication`, `config-repo/application.yml`, `spring.config.import=configserver:` in every service | `http://localhost:8888/{service}/default` | Shared JWT secret, Eureka URL, actuator exposure, logging pattern all sourced from one file | `curl http://localhost:8888/auth-service/default` returns merged config |
| 5 | JWT authentication | auth-service | `JwtService`, `AuthServiceImpl.login`, `AuthController` | `POST /api/auth/login` | Login returns a signed HS256 JWT | `curl -X POST .../api/auth/login` → `{"token": "eyJ..."}` |
| 6 | JWT authorization / RBAC (ADMIN, MANAGER, VIEWER) | auth-service, api-gateway | `SecurityConfig` (`hasRole`), `JwtAuthenticationGlobalFilter`, `Role`/`User` entities | `GET /api/auth/users` (ADMIN only) | Non-admin JWT is rejected with 403 | Login as MANAGER, call `/api/auth/users` → 403 |
| 7 | 401 Unauthorized handling | api-gateway, auth-service | `JwtAuthenticationGlobalFilter.unauthorized()`, `SecurityConfig` entry point | any protected route without/with bad JWT | RFC9457 problem+json body with status 401 | `curl .../api/shipments` with no header → 401 |
| 8 | 403 Forbidden handling | auth-service (+ pattern reusable per service) | `SecurityConfig.accessDeniedHandler`, `GlobalExceptionHandler.handleAccessDenied` | `GET /api/auth/users` as non-admin | RFC9457 problem+json body with status 403 | See row 6 |
| 9 | Correlation IDs across services | common, api-gateway, all services | `CorrelationIdGlobalFilter` (gateway), `CorrelationIdFilter` (MVC services) | every request | `X-Correlation-Id` generated at the edge, propagated and echoed by every hop, present in every log line | Inspect response headers + logs for a matching id end-to-end |
| 10 | Rate limiting (429) | api-gateway | `RateLimiterConfig`, Redis-backed `RequestRateLimiter` filter per route | any gated route | `X-RateLimit-*` headers on every response; 429 once burst is exhausted | Script >60 rapid requests to `/api/shipments`, observe `X-RateLimit-Remaining` fall then 429 |
| 11 | Circuit breaker | api-gateway, quote-service | Gateway `CircuitBreaker` filter + `FallbackController`; `CountryLookupService` (`@CircuitBreaker`) | `/fallback/{service}`; quote creation | Stopping a downstream service trips the breaker to a 503 fallback | `docker stop shiptrack-country-service`; request a quote repeatedly → circuit opens, fallback pricing used |
| 12 | Retry | quote-service | `CountryLookupService` (`@Retry(name="countryService")`) | `POST /api/quotes` | Transient Feign failures to Country Service are retried before failing | Config: `resilience4j.retry.instances.countryService.max-attempts=3` |
| 13 | Timeout | quote-service, api-gateway | Feign `connect-timeout`/`read-timeout` config; Gateway `httpclient` timeouts | `POST /api/quotes`; any gateway route | Slow downstream calls are bounded, not indefinite | Config values in `quote-service/application.yml` and `api-gateway/application.yml` |
| 14 | RFC 9457 Problem Details | common (+ every service) | `ProblemDetailFactory`, `GlobalExceptionHandler` | every error response | Every 4xx/5xx returns `application/problem+json` with `type`, `title`, `status`, `detail`, `correlationId` | `curl -i .../api/shipments/999` → 404 problem+json |
| 15 | ETag / conditional GET (304) | shipment-service | `Shipment.etag()`, `ShipmentController.getById` | `GET /api/shipments/{id}` | `If-None-Match` matching current ETag returns 304 with empty body | Verified live: 201 → ETag `"1-0"` → `If-None-Match` GET → 304 |
| 16 | Optimistic locking / If-Match (412) | shipment-service | `@Version` on `Shipment`, `ShipmentController.parseVersionFromEtag`, `ShipmentServiceImpl.patch` | `PATCH /api/shipments/{id}` | PATCH without/with stale `If-Match` → 412; correct ETag → 200 with new ETag | Verified live: PATCH w/o `If-Match` → 412; PATCH with `If-Match: "1-0"` → 200, version 1 |
| 17 | Idempotency-Key support | shipment-service | `IdempotencyKey` entity, `ShipmentServiceImpl.create` | `POST /api/shipments` with `Idempotency-Key` header | Same key + same body replays the original 201 response as 200 | Verified live: same key posted twice → 201 then 200, identical body |
| 18 | Pagination | shipment-service, quote-service, auth-service | `Pageable` parameters, Spring Data `Page<T>` | `GET /api/shipments`, `GET /api/quotes`, `GET /api/auth/users` | Standard `page`/`size`/`sort` query params, `Page` envelope in response | `curl .../api/shipments?page=0&size=10` |
| 19 | Cursor-based pagination | tracking-service | `TrackingEventCursorRepository`, `CursorPage` DTO | `GET /api/events?cursor=&limit=` | MongoDB ObjectId-based cursor, stable under concurrent inserts | Verified live: `GET /api/events?limit=5` → `{"items":[...],"nextCursor":null,"hasMore":false}` |
| 20 | Content negotiation (JSON + XML) | shipment-service | `jackson-dataformat-xml`, `produces={APPLICATION_JSON,APPLICATION_XML}` on `ShipmentController` | `GET /api/shipments/{id}` with `Accept: application/xml` | Same resource served as JSON or XML based on `Accept` header | `curl -H "Accept: application/xml" .../api/shipments/1` |
| 21 | Cache-Control headers | shipment-service | `CacheControl.maxAge(...)` / `CacheControl.noStore()` in `ShipmentController` | `GET /api/shipments`, `GET /api/shipments/{id}`, mutating endpoints | GETs are cacheable for 30s; writes are `no-store` | `curl -i .../api/shipments/1` → `Cache-Control: private, max-age=30` |
